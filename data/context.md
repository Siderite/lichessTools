# LiChess Tools — Context for `data/`

Folder-level context file for the static datasets shipped inside the extension. Verified against the current tree (36 files in `scripts/`, 12 here, extension version `2.5.9`, refreshed 2026-10-30). See the [root `context.md`](../context.md) for the project overview and [`scripts/context.md`](../scripts/context.md) for the scripts that read these files.

## How the folder is read

Nothing in the manifests names these files: no `data/` path appears in `content_scripts` or in `web_accessible_resources`. They are reached only at runtime:

- `lt.comm.getData('x.json')` (`scripts/lichessTools-comm.js`) prefixes the folder, sending `{type: 'getFile', options: {filename: 'data/x.json'}}` as a `LichessTools.send` CustomEvent, with up to 3 retries.
- The isolated-world listener `scripts/lichessTools-comm-proxy.js` answers most of those locally (`fetch(chrome.runtime.getURL('data/x.json'))`), falling back to `scripts/service_worker.js`, which has the same `getFile` handler.
- The JSON is parsed by the handler and memoized per filename in `Comm._files`, so a file is fetched at most once per page.
- Callers always treat a missing file as a warning (`Could not load ...!`) and disable the feature, never throw.

## Key encoding of position-keyed files

`openings.json`, `wikiUrls.json` and `gambits.json` are keyed by LiChessTools position keys, produced by `lt.getPositionFromFen(fen)`: the first two FEN fields concatenated with `/` removed and everything from the first `,` dropped (the en-passant field is cut, castling rights and the counters are kept when `deep`). Example: `rnbqkbnrpppppppp8888PPPPPPPPRNBQKBNRw`. `gambits.json` uses the same idea but with per-piece counts (`r1b1k1nrpppp1ppp...`) generated by the AssetGenerator rather than by `getPositionFromFen`.

## Generation and provenance

`data/README.md` states verbatim: *Generate the following files with AssetGenerator from LiChessToolsAdjacent: `countries.json`, `crowdin.json`, `flairs.json`, `gambits.json`, `openings.json`, `wikiUrls.json`.* So those six are regenerated from the companion project (https://github.com/Siderite/lichessToolsAdjacent) and are not hand-edited; the remaining five (`boards`, `pawnStructures`, `pieceSets`, `quotes`, `soundThemeUrls`) are curated in this repo.

`HISTORY.md` records the corresponding feature landings: openings list embedded (2.4 era), study flairs, gambits on Explorer, FEN wiki URLs, Crowdin integration (started at 12 languages, now 23 locales shipped), new boards and piece sets.

## Caveats and cross-references

- Position-keyed lookups must build the key the same way the generator did (`lt.getPositionFromFen`), and case/side-to-move matters: the trailing `w`/`b` is part of the key.
- `showOpening` mirrors positions with `LiChessTools.ChessMetrics.mirrorFen(fen)` and appends ` (R)`; `showPawnStructure` mirrors through `LiChessTools.PawnStructure.getOpposingStructure(structure)` and also appends ` (R)`. Both therefore need the mirrored dataset entry to exist, not just the exact one.
- `wikiUrls.json` values are wiki page titles (`Chess Opening Theory/1. e4`), and `tools/wikiFen` re-parses them into `ply`/`san` nodes with `/\/\d+\.+[\s_]*([^\s_\/]+)/g`; keys whose title does not match the current path are skipped.
- `crowdin.json` layers are named `<lang>-crowdin` in `lt.intl`; `LiChessTools.Translator.get lang` accepts them, so a page in one of the 23 locales gets the whole 1 335-key table. `tools/crowdin` skips loading when `html[lang]` starts with `en`.
- `tools/showPawnStructure` also renders the Euwe-Kramer code link using `pawnStructures.html#ek-<code>` (`getEuweKramerUrl(code)`), i.e. the same document the `url`s in `pawnStructures.json` point into.
- `flairs.json` is the only dataset consumed by a script rather than a tool (`LiChessTools.Api.flair.getFlairs`); every other file has exactly one tool consumer, listed above.
- Nothing in `data/` is minified or compressed in the package; `Comm` keeps the parsed objects in memory, and only `tools/showFlags` additionally persists part of one (`LiChessTools.countryCache` in storage).
- No content in the root `context.md` was about this folder, so `data/context.md` started from scratch; the pointer to it now lives under `## Architecture` in the root file.
