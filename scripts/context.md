# LiChess Tools — Context for `scripts/`

Folder-level context file. It covers every file in `scripts/` **except `lichessTools.js` itself**, which is the singleton described in the root [`context.md`](../context.md). Verified against the current source tree (extension version `2.5.9` in all four manifests, 36 files in this folder, refreshed 2026-10-30).

## Loading order (`manifest.json` / `manifest.json.chrome` / `manifest.json.edge` / `manifest.json.ff`)

All four manifests ship the same script set. `manifest.json`, `manifest.json.chrome` and `manifest.json.edge` are `manifest_version: 3`; `manifest.json.ff` is `manifest_version: 2` (uses `browser_action` + `browser_specific_settings`). All report `"version": "2.5.9"`.

| Content-script block | `run_at` | `world` | contents |
|---|---|---|---|
| 1 | `document_start` | `MAIN` | 27 files, in this order: `cash.min.js`, `cash.extra.js`, `lichessTools.js`, `lichessTools-location.js`, `lichessTools-translator.js`, `lichessTools-network.js`, `lichessTools-storage.js`, `lichessTools-comm.js`, `lichessTools-cache.js`, `lichessTools-api.js`, `lichessTools-toolBase.js`, `lichessTools-indexedDbStorage.js`, `lichessTools-apiSemaphore.js`, `lichessTools-maxSizedMap.js`, then the 13 `lichessTools-chessMetrics-*.js` files in dependency order: `Material`, `Scoring`, `MoveGen`, `FenDistance`, `PawnStructure`, `ChessMetrics`, `EuweKramer`, `BrilliantMoveAnalyzer`, `ChessKmapsEvaluator`, `ChessActivityEvaluator`, `CoordinationCalculator`, `ChessPositionValuator`, `PositionDifficultyEvaluator` |
| 2 | `document_start` | `MAIN` | `dragDropTouch.js`, `zip.js`, `URLpolyfill.js`, then the whole `tools/` script set, ending with `lichessTools-init.js` (176 js entries in the block) |
| 3 | `document_end` | `MAIN` | `lichessTools-start.js` |
| 4 | `document_start` | *no `world` key → isolated world* | `lichessTools-comm-proxy.js` |

Outside the content scripts:
- `background.service_worker` = `scripts/service_worker.js`; its first line is `if (globalThis.importScripts) importScripts('obs-websocket.js');`, which is the only use of `obs-websocket.js`.
- `popup.html` loads `scripts/popup.js` (the browser-action popup page).
- `web_accessible_resources` lists only `tools/` artefacts (`chessops.bundle.mjs`, `d3.bundle.mjs`, `nouislider.bundle.mjs`, `fontIcons/lichessTools.woff2`, the two `chessPursuit` `.dat` files) — nothing from `scripts/` or `data/`.

Order matters because each file only appends itself to one global namespace as it executes:
- `lichessTools-toolBase.js:121` and `lichessTools.js:2028` assign `window.LiChessTools = LiChessTools`.
- `lichessTools-toolBase.js:116` seeds `LiChessTools.Tools = { ToolBase, PageToolBase }`; each `tools/*/tool.js` adds its class to that object.
- `lichessTools-init.js:1` builds the singleton: `window.lichessTools = new LiChessTools(window, cash)` (`cash` is the global exported by `cash.min.js`), then issues 171 `loadTool(...)` calls (169 active; `InterceptTimeouts` and `FixChessvision` are commented out), and finishes with `lichessTools.init()`.
- `lichessTools-start.js` runs at `document_end`: it waits until `window.site?.info` exists (polling every 100 ms) and then calls `lichessTools.start(window.site)` after a further 100 ms delay.
- Infrastructure tools still load first inside `init.js` (`PageInitData`, `EmitCeval`, `EmitRedraw`, `InterceptEventHandlers`, `FixAbortController`, ...), then feature tools, then command tools, and `Preferences`, `KeyShortcuts` / `KeyboardHelp` last.

## Cash — the DOM layer (`cash.min.js`, `cash.extra.js`)

- `cash.min.js` — vendored [CASH](https://github.com/fabiospampinato/cash) (MIT), minified. Exposes the global `cash`, which `lichessTools-init.js` hands to the singleton as `lt.$`; every tool uses `$` for querying, creating and binding DOM nodes.
- `cash.extra.js` — an IIFE `(function(cash){ ... })(cash)` adding the LiChessTools-specific helpers on top of stock CASH:
  - `cash.cached(selector, duration = 10000)` — memoizes a query in `cash.__cache` as `{value, time, duration}`, re-running only when the entry is stale; logs `Getting ... from $ cache` when `window.lichessTools.debug > 2`.
  - `cash.single(selector, context)` — first match, cash-wrapped.
  - `cash.createToggle(id, text, title, name)` — builds Lichess `cmn-toggle-wrap` / `cmn-toggle` checkbox markup (dialog and preferences flows).
  - `cash.fn.*` instance helpers: `toggleDisplay(value, important)` (restores `initDisplay`, honours `!important`), `attrSafe`, `textSafe`, `removeAttrSafe` (write only when the value differs), `selectText(start, length)` and `insertText(value, focus)` (textarea caret/selection maths for the dialog and CLI inputs), `toggleClassSafe(className, value)` (throws on `undefined` value, accepts a per-element function, defers via `requestAnimationFrame` above 100 elements), `appendSpan(text)`, `observer()` (MutationObserver wrapper), `replaceText(replacement, onlyIfExisting)`, `makeCombo(options)` (dropdown combo behind the custom-board-image dialog — installs listeners with no teardown pass), `eachAsync(func)` (`Promise.all` of per-element async passes).

## `ToolBase` and `PageToolBase` (`lichessTools-toolBase.js`)

- `ToolBase` — the base every tool extends: `get name()` (constructor name minus the trailing `Tool`), `logOption(label, value)` (violet console log used in `start()` traces), and empty `async init()` / `async start()` hooks.
- `PageToolBase extends ToolBase` — tools that own an entire page instead of an element on a Lichess page:
  - fields: `pageUrl` (owned path; Lichess answers unknown paths with a 404 shell that gets taken over), `pageAliases` (entries `{url, test?, convert?}` — an entry without `url` matches any page, letting a tool release a hash it used to hijack), `pageCss` (Lichess stylesheets loaded together through `lt.loadCss`), `pageContainer` (default `'#main-wrap main'`), `pageClass` (class put on the container and the key its css uses — the tool key, so the tool may rename its page freely), `pageSpinner`.
  - methods: `isPage(url = pageUrl)` (exact `lt.location.pathname` match; a tool page has no subpaths or parameters), `gotoPage(hash)`, `redirectPageAliases()` (`true` means the browser was sent away and the caller must stop), `loadPageCss`, `preparePage(spinner = true)` (alias redirect → css load → empties `pageContainer`, tags it `lichessTools-<pageClass>`, appends `lt.spinnerHtml`; returns `null` when the tool does not own the page), `initPageEvents(container)` (`lt.uiApi.initializeDom` then spinner removal; called at the end of a render).
  - Page tools in the current tree: `tools/lichessLadders` (`pageUrl = '/page/lichessLadders'`, `pageClass = 'lichessLadders'`) and `tools/preferences` (`pageUrl = '/page/ltPreferences'`, `pageClass = 'preferences'`). `tools/pgnEditor` and `tools/calculationTrainer` now extend plain `ToolBase` — the PGN Editor went back to popup mode on 30 Oct and `calculationTrainer` declares no `pageUrl`/`pageClass`.
- The file also performs the namespace seeding described above (`LiChessTools.Tools`, `window.LiChessTools`).

## Entry points, polyfills and vendored files

- `lichessTools-init.js` — instantiates the singleton (`new LiChessTools(window, cash)`), then `loadTool()` 171 times (169 active, `InterceptTimeouts` and `FixChessvision` commented out), then `lichessTools.init()`. The order is the dependency order: emitters and fixes first (`PageInitData`, `Crowdin`, `FontIcons`, `EmitCeval`, `EmitRedraw`, `EmitContentLoaded`, `SoundOptions`, `MuteOwnMoves`, `AddNotifications`, `Dialog`, `DailyQuote`, `Feedback`, `EmitEsmLoaded`, `InterceptEventHandlers`, `FixAbortController`, `FixSnabdom`, `FixChessgroundResize`, `FixWakeLock`, `EmitChapterChange`, `EmitCommentChange`, `EmitPuzzleChange`, ...), library tools (`ChessOps`, `D3`, `NoUiSlider`, `Stockfish`), then feature tools, then command tools, finally `Preferences`, `KeyShortcuts`, `KeyboardHelp`.
- `lichessTools-start.js` — `document_end` entry: polls until `window.site?.info` exists, then `lichessTools.start(window.site)` 100 ms later. This is where tools get the Lichess page objects.
- `dragDropTouch.js` — exposes `LiChessTools.enableMobileDragAndDrop`, a wrapper around Microsoft's DragDropTouch singleton (`_ISPRESSHOLDMODE = false`, `_PRESSHOLDAWAIT = 400`, `_PRESSHOLDMARGIN = 25`, `_PRESSHOLDTHRESHOLD = 0`, `_CTXMENU = 900`). Only caller: `tools/resizeExplorer`.
- `zip.js` — `LiChessTools.zip(text)` / `LiChessTools.unzip(text)`; an LZ-string-style codec (Pieroxy, WTFPL) used by `Storage` for values above the zip threshold, marked by the `LTPK` prefix.
- `URLpolyfill.js` — polyfills `URL.canParse` and `URL.parse` on browsers that lack them.
- `obs-websocket.js` — minified obs-websocket client (JSON protocol class); used only by `service_worker.js` through `importScripts`.
- `popup.js` — the browser-action popup page script (`popup.html` line 89): sets `#mainTitle` `title` to the manifest description and its text to manifest name + version; on `window.chrome`, registers `chrome.runtime.requestUpdateCheck` and, when an update is available, marks `div.link a.update` with class `needsIt` and intercepts its click to open `chrome://extensions`; points `div.link a.rate` at the Firefox add-on page when `window.browser` is set, otherwise the Chrome Web Store URL.

## Cross-cutting notes

- `scripts/lichessTools.js` (66 KB, 2 029 lines) is deliberately **not** documented here — see the root [`context.md`](../context.md).
- Namespace seeding happens in `lichessTools-toolBase.js`, which is why it must load before any `tools/*.js`; it defines `LiChessTools.Tools = { ToolBase, PageToolBase }` and assigns `window.LiChessTools`.
- `Comm.getData('x.json')` prefixes `data/`, so these files are read through the `getFile` handler — either the isolated-world `handleLocally` in `lichessTools-comm-proxy.js` (`fetch(chrome.runtime.getURL('data/x.json'))`) or the same handler in the service worker. Results are memoized in `Comm._files`. See `data/context.md` for the contents of that folder.
- `APISemaphore` and `IndexedDbStorage` have no tool-level consumers: `Cache.init()` builds an `APISemaphore` and `Storage.getStore` builds an `IndexedDbStorage`. `FenDistance` currently has no consumer at all — it is staged for the position-info metrics work (issue #1393) and exercised only by `test/fenDistance.check.js`.
- Scratch harnesses for these scripts live in `test/` (`fenDistance.check.js`, `zipcheck.check.mjs`, `localDatabase.check.js`, `_tmp_manifestcheck.js`, ...), run with `node test/<file>`; `test/` is gitignored, and `build.bat` skips both `test/` and any file named `context.md` when zipping the store packages.
- Bug-hunt packets and reports under `.cline/bughunt/` quote these files with line-numbered source; treat them as historical evidence, not current state.
